# M4 · 体验升级方案（回答溯源 + 持久化记忆 + 意图识别 + 前端升级）

> 前置：M2 完成（sources 已随 done 事件透传）、M3 完成（agent 模式可切换）
> 目标：回答可溯源（引用面板可见）、会话记忆持久化（重启不丢）、意图识别自动路由（独立小模型可配）、前端具备模式开关
> 验收：提问后页面下方展示引用来源列表；重启服务后会话上下文仍在；auto 模式下意图识别自动分流三条链路，小模型可独立配置

## 一、范围

**做**
- 溯源 UI：done 事件携带 sources（M2 已透传），前端渲染来源面板；正文 [n] 角标样式化
- 持久化记忆：Redis 存储（会话消息 JSON，TTL 7 天），配置可切换 `memory | redis`，接口不变
- 意图识别：独立小模型可配（`rag.intent.*`，缺省回退主 LLM），输出意图枚举 + 置信度，按路由表自动分流
- 前端升级：问答模式四选一（auto / 普通 / RAG / Agent）、新会话按钮（重置 sessionId）、来源面板
- 重启后 SSE 断线不白屏（前端自动提示重连）

**不做**
- 不做多会话历史列表 UI（会话数据都在 Redis，接口预留 GET /api/conversations）
- 不做记忆摘要压缩 / 长期向量记忆（已在 MVP 方案明确砍掉）
- 不做树形意图 / 多级意图分类（ragent 那套重了，四类扁平枚举够用）
- 不做规则前置（明显闲聊先规则判的优化留后续增强）
- 不做用户体系与鉴权

## 二、核心设计

### 溯源数据流（打通 M2 遗留）

```
M2：HybridRetriever → RetrievedChunk(chunkId, content, docName, rrfScore)
     → ChatController 组装 sources: [{n, docName, snippet(前80字)}]
     → done 事件 data: {sessionId, sources}
M4：前端 done 处理 → 渲染来源面板（编号/文档名/片段预览）
     → 正文 [n] 用 <sup> 角标样式
```

- Agent 模式（M3）若经过 search_knowledge_base 工具，同样收集其 sources 随 done 下发（AgentContext 增加 sources 收集器）

### 持久化记忆（Redis）

```java
public interface ConversationMemory {                 // 从 @Component 抽成接口
    List<ChatMessage> load(String sessionId, int maxMessages);
    void append(String sessionId, ChatMessage message);
    void clear(String sessionId);
}
```

- `InMemoryConversationMemory`（现状实现，默认）
- `RedisConversationMemory`：`StringRedisTemplate`，key = `chat:memory:{sessionId}`，value = JSON 数组
  - append：读出 → 追加 → 写回（每条全量重写，消息量 ≤20 条，成本可忽略），EXPIRE 7 天
  - 简单可靠，避免引入 Stream/List 结构的复杂度
- 配置：`rag.memory.type: memory | redis`，`@Configuration` 按类型装配（单 Bean 条件装配）

### 意图识别与自动路由（独立小模型可配）

```
intent/
├── Intent.java            # 枚举：CHAT / KB_QA / TOOL_TASK / OFF_TOPIC
├── IntentProperties.java  # rag.intent 配置
└── IntentClassifier.java  # 单次同步调用小模型，输出 Intent + confidence
```

**配置（IntentProperties，缺省回退主 LLM）**

```yaml
rag.intent:
  enabled: true                      # 关闭则 auto 模式退化为隐式路由（M2 行为）
  base-url: ""                       # 空 → 回退 llm.base-url；独立小模型/vLLM 时填自己的
  model: ""                          # 空 → 回退 llm.model；如 Qwen/Qwen2.5-7B-Instruct
  api-key: ""                        # 空 → 回退 llm.api-key
  timeout-seconds: 5                 # 短于主 LLM（小模型快）
  confidence-threshold: 0.6          # 低于阈值回退隐式路由
```

> vLLM 场景零代码迁移：服务器部署小模型后，仅改 `base-url` 指向 `http://内网IP:8000/v1` + `model` 填自部署模型名（vLLM 暴露标准 OpenAI 兼容 API，与 LlmClient 协议一致）。

**分类调用（IntentClassifier）**

- 复用 `LlmClient.chat`（同步、temperature 0、thinking=false），消息仅两条：system（分类指令 + 四类定义与示例）+ user（原问题）
- 要求输出纯 JSON：`{"intent": "KB_QA", "confidence": 0.9}`；解析失败/超时/异常 → 降级（不抛出）
- 降级策略：返回 `Intent.UNKNOWN`，路由层收到 UNKNOWN → 走 M2 隐式路由（检索有结果 RAG、无结果纯对话）

**路由表（ChatController mode=auto 时）**

| Intent | 分流 |
|---|---|
| CHAT / OFF_TOPIC | plain（不检索） |
| KB_QA | rag |
| TOOL_TASK | agent |
| UNKNOWN（降级/低置信） | 隐式路由（检索兜底） |

### 前端升级（index.html）

- 顶部模式切换：四选一（**auto（默认）/ 普通对话 / 知识库问答 / Agent**），对应 `chat` 请求参数 `mode: auto | plain | rag | agent`
- 请求体统一为 `{sessionId, message, mode}`（M2/M3 的 `kb`/`agent` 参数收敛为 `mode`，保留旧参数兼容一个版本）
- 新会话按钮：清空消息区 + 重新生成 sessionId + 清 Redis 记忆（DELETE /api/memory/{sessionId}）
- 来源面板：done 事件渲染，样式与气泡区一致

## 六、关键取舍（面试可讲）

1. **记忆全量重写而非 Redis List 追加**：消息量小（N 轮窗口），全量 JSON 重写最简单且原子；不值得引入 Stream 复杂度
2. **接口抽象先行、实现可切换**：内存版保证零依赖可跑，Redis 版保证生产语义，配置一键切换
3. **sources 随 done 一次性下发而非增量**：来源数量少、时机在回答结束后，无需增量协议
4. **意图识别独立小模型 + 缺省回退主 LLM**：不配则复用主模型零成本起步；配了则小模型省成本降延迟，且 vLLM 自部署迁移只改 base-url（OpenAI 兼容协议一致），零代码改动
5. **意图失败降级隐式路由而非报错**：意图识别是路由增强不是依赖，M2「检索有无」的隐式路由天然兜底，模块挂掉系统不瘫
6. **四类扁平枚举而非树形意图**：单知识库 + 两工具的规模不需要多级分类；ragent 的树形意图服务于多知识库/多工具矩阵，这里做扁平够用，YAGNI
7. **不做规则前置**：每次多一次小模型调用（几百 ms、近零成本）先接受；「规则优先 + LLM 兜底」留作有真实延迟诉求时的增强项

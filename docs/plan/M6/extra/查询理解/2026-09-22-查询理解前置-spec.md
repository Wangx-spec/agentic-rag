# 查询理解前置（AGENT 规划期）+ r09 消融 Spec

> 日期：2026-09-22 ｜ 阶段：准确率轨收尾（M6 后续） ｜ 前置：r07d 为定版基准

## 背景

- 定版基准 r07d（AGENT + rerank + 引用裁剪 top5）：recall 68.28 / corr 43.75 / 满分 28 题，answers 零泄漏。
- 最大短板是泛化性：v1 去术语化变体（同一 64 题改成口语问法）recall 只有 40.23，比原题低 28.1pp，远超 <15pp 的门槛；v2 短查询低 12.6pp（达标线边缘）。
- 现有查询改写只在检索层按次触发（同义词改写），且 AGENT 模式下模型自己组织 tool 查询——口语问题进来时，模型写出的检索查询质量差，改写在下游救不回来。
- 另有遗留短板「要求拼全多篇文档的题目答对率仍低」，与 MULTI_TASK 子问题拆解直接相关。
- 项目已有意图分类器（五类意图，用于 AUTO 路由），与查询理解存在天然合并点：都是「规划期先理解问题」。

## 目标

- 在 AGENT 模式的 ReAct 循环开始前，新增一步查询理解：一次 LLM 调用同时产出「意图 + 规范查询」（MULTI_TASK 时额外产出子查询列表），替代现有单独的分类调用，省一次 LLM 往返。
- 规范查询/子查询注入 Agent 规划上下文，引导模型用检索友好的问法调用知识库检索工具。
- 用 r09 消融验证：r07d 口径不变、唯一变量是开启查询理解；原题 64 题确认不回退，v1 变体验证 recall 差距从 -28.1pp 收窄到 <15pp。
- 全程 fail-open：查询理解失败/超时/输出解析失败时，跳过该步骤，Agent 按原问题正常跑。

## 功能需求

- **F1: 查询理解步骤（AGENT 规划期前置）**
  - 触发时机：AGENT 模式下，ReAct 循环开始之前，对用户原始问题执行一次。
  - 产出：一次 LLM 调用返回结构化结果——意图（沿用现有五类枚举）+ 规范查询；意图为 MULTI_TASK 时额外产出子查询列表（每个独立子问题一条）。
  - 规范查询要求：保留原意、补全术语/展开缩写、检索友好；不是改写用户问题本身，而是给 Agent 的「检索建议」。

- **F2: 替代现有分类调用**
  - AGENT 模式下，这一步同时承担现有意图分类职责，不再单独调一次分类（省一次 LLM 往返）；意图结果继续供路由/模式判断使用，口径与现有五类一致。
  - RAG / MULTI_AGENT / AUTO 模式的现有意图逻辑不改动（本期只动 AGENT 链路）。

- **F3: 规划上下文注入**
  - 查询理解结果以一条「检索引导」信息注入 Agent 上下文：包含规范查询（及子查询列表），并明确指示 Agent 优先用这些查询调知识库检索工具，最终作答仍须对齐用户原始问题。
  - 原始问题保留在上下文中不被替换（作答对齐与引用判分口径不变）。

- **F4: 故障开放（fail-open）**
  - 查询理解 LLM 调用失败、超时、输出非合法 JSON、意图不在五类枚举内——任一发生，静默跳过该步骤，Agent 按原问题进入 ReAct 循环，主流程不中断、不报错给用户。

- **F5: 开关与配置**
  - 查询理解有独立开关（默认开启，可用环境变量关闭），关闭时行为完全回退 r07d 口径，保证定版复测可控。

- **F6: r09 消融评测**
  - r07d 口径不变（AGENT + hybrid + 改写 + HyDE + rerank + citationTopN=5 + 文档工具开关关闭），唯一变量是开启查询理解。
  - 跑两轮：原题 64 题（对照 r07d 确认不回退）+ v1 去术语化变体 64 题（对照 v1 基线 40.23 验证提升），四指标同口径对比归档。

## 非功能需求

- N1: 开关、超时等可通过配置/环境变量调整，无需改代码（与现有引用裁剪上限、文档工具开关同一风格）。
- N2: 查询理解只增加一次 LLM 调用（合并分类职责后净增为零），单次延迟在评测超时预算内可忽略。
- N3: 解析健壮性：LLM 输出容忍 markdown 代码块包裹、多余空白；字段缺失时按 fail-open 处理（复用现有意图分类的解析容错思路）。
- N4: 单元测试覆盖：正常三类意图产出、MULTI_TASK 子查询、非法 JSON、未知意图、LLM 异常、开关关闭六类路径。

## 不做的事

- 不改 RAG / MULTI_AGENT / AUTO 模式的意图与检索链路（本期只动 AGENT 链路）。
- 不做 rerank 阈值过滤（另一独立提案，单独评估）。
- 不新增意图类型、不动现有五类枚举定义。
- 不做跨语言（中译）检索能力建设（v3 仅作参考指标，不在本期目标内）。
- 不改检索层查询改写逻辑（改写仍在下游生效，与规划期前置叠加不冲突）。
- 不重复运行多轮验证采样方差（沿用 r08b 的单次运行判定纪律）。

## 验收标准

- AC1（对 F1/F2）：AGENT 模式提问时，日志可见一次查询理解调用，产出意图+规范查询；MULTI_TASK 问题时产出子查询列表；全程不再有独立的意图分类调用。
- AC2（对 F3）：Agent 上下文中出现检索引导信息且包含规范查询；最终 answers 文件结构不变（question_id / answer / document_ids），原始问题仍用于作答对齐。
- AC3（对 F4）：分别模拟 LLM 异常、非法 JSON、未知意图三种故障，Agent 均正常进入 ReAct 循环并产出答案，无未捕获异常（单测覆盖）。
- AC4（对 F5）：开关关闭时，启动后无任何查询理解调用，行为与 r07d 完全一致。
- AC5（对 F6）：r09 两轮（原题+v1）作答与判分完成；原题四指标相对 r07d 无显著回退（corr 波动在 ±3pp 内），v1 recall 相对原题的差距收窄到 <15pp（即 v1 recall ≥ 原题 recall - 15）。

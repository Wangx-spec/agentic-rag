## 步骤 1：基础设施 — 线程池配置 + DTO 数据模型

**做什么**：创建多 Agent 专用线程池（与主线程池隔离，避免并行子任务挤占聊天线程），并定义子任务结果数据结构。

| 操作 | 文件 | 方法 / 说明 |
|---|---|---|
| **新建** | `config/ExecutorConfig.java` | `@Bean multiAgentExecutor()` — core=2, max=8, CallerRunsPolicy |
| **新建** | `multiagent/dto/SubTaskResult.java` | record：`index(int)`, `question(String)`, `conclusion(String)`, `sources(List<RetrievedChunk>)`, `success(boolean)`, `error(String)` |

**依赖**：无（纯数据结构 + Spring Bean 配置）

---

## 步骤 2：LeaderAgent — 问题拆解器

**做什么**：LLM 将复合问题拆解为子问题列表（JSON 输出），解析失败时降级为单问题（原问题直答），上限截断 4 个。

| 操作 | 文件 | 方法 |
|---|---|---|
| **新建** | `multiagent/LeaderAgent.java` | `plan(String question)` → `List<String>` |
| | | `private parsePlanResponse(String llmResponse)` → 解析 JSON `{"subQuestions": [...]}` |
| | | `private buildPlanPrompt(String question)` → 构造拆解 system prompt |
| | | `private fallbackToSingle(String question)` → 解析失败返回单元素列表 |

**依赖**：`LlmClient`（已有）

---

## 步骤 3：SubAgentExecutor — 子任务执行器

**做什么**：每个子问题独立走「检索 → 生成子结论」，失败不抛异常，返回带 `success=false` 的结果。

| 操作 | 文件 | 方法 |
|---|---|---|
| **新建** | `multiagent/SubAgentExecutor.java` | `execute(String subQuestion, int index)` → `SubTaskResult` |
| | | `private buildSubConclusionPrompt(String subQuestion, List<RetrievedChunk> chunks)` → 构造「子问题 + 检索片段 → 带 [n] 引用的结论」prompt |
| | | `private String generateSubConclusion(List<ChatMessage> messages)` → 同步调用 LLM（非流式） |

**依赖**：`HybridRetriever`（已有）、`LlmClient`（已有）

---

## 步骤 4：Aggregator — 汇总器

**做什么**：原问题 + 所有成功子结论 → LLM 流式生成最终回答，合并去重 sources。

| 操作 | 文件 | 方法 |
|---|---|---|
| **新建** | `multiagent/Aggregator.java` | `aggregate(String question, List<SubTaskResult> results, SseEmitter emitter)` → `void`（流式输出 delta 到 emitter） |
| | | `private buildAggregatePrompt(String question, List<SubTaskResult> results)` → 构造汇总 prompt |
| | | `private mergeSources(List<SubTaskResult> results)` → `List<RetrievedChunk>` 合并去重（按 rank / docName 去重，保留唯一引用） |

**依赖**：`LlmClient`（已有）

---

## 步骤 5：MultiAgentOrchestrator — 编排器

**做什么**：串联 Leader → SubAgent(并行) → Aggregator 三步，推送 SSE 过程事件，处理全失败降级（回退普通 RAG 链路）。

| 操作 | 文件 | 方法 |
|---|---|---|
| **新建** | `multiagent/MultiAgentOrchestrator.java` | `orchestrate(String question, SseEmitter emitter, String sessionId, ConversationMemory memory)` → `boolean`（true=多Agent完成；false=降级需走RAG，触发条件：①Leader拆解仅1个子问题 ②全部子任务失败） |
| | | `private void emitThinking(SseEmitter emitter, String text)` → 推送 thinking 事件 |
| | | `private List<SubTaskResult> executeSubTasksInParallel(List<String> subQuestions, ExecutorService executor)` → `CompletableFuture` 线程池并行调度 |
| | | `private List<SubTaskResult> filterSuccessful(List<SubTaskResult> results)` → 过滤成功的结果 |

**SSE 事件序列**：
```
[多Agent] 拆解完成：N 个子问题
[多Agent] 子任务 n 开始：{子问题文本}
[多Agent] 子任务 n 完成
[多Agent] 开始汇总回答
```

**依赖**：`LeaderAgent`（步骤 2）、`SubAgentExecutor`（步骤 3）、`Aggregator`（步骤 4）、`multiAgentExecutor`（步骤 1）

## 步骤 6：Intent 枚举 + 分类器更新

**做什么**：意图枚举新增 `MULTI_TASK`，分类 prompt 补充复合问题判定定义与正反例（宁可漏判不可误判）。

| 操作 | 文件 | 改动内容 |
|---|---|---|
| **改** | `intent/Intent.java` | 枚举新增 `MULTI_TASK` |
| **改** | `intent/IntentClassifier.java` | `SYSTEM_PROMPT` 常量补充 MULTI_TASK 定义与示例：正例「A 是什么？A 和 B 有什么区别？」→ MULTI_TASK；反例「什么是 RAG？」→ KB_QA；要求"仅当问题明确包含多个独立子问题时才判 MULTI_TASK，不确定时倾向单链路" |

**依赖**：无（纯修改已有枚举和字符串常量）

## 步骤 7：ChatController 接入

**做什么**：auto 模式识别到 `MULTI_TASK` 自动进入多 Agent 链路；新增显式 `mode=multi-agent` 兜底入口。

| 操作 | 文件 | 方法 / 改动 |
|---|---|---|
| **改** | `api/ChatController.java` | `ChatMode` 枚举新增 `MULTI_AGENT` |
| | | `ChatMode.from()` 新增 case `"multi-agent"` → `MULTI_AGENT` |
| | | `handleChat()` switch 新增 `case MULTI_AGENT` → 调用 `runMultiAgent()` |
| | | `runAuto()` switch 新增 `case MULTI_TASK` → 调用 `runMultiAgent()` |
| | | **新增** `private void runMultiAgent(SseEmitter emitter, String sessionId, String userMessage)` — 调用 `MultiAgentOrchestrator.orchestrate()`，返回 false 时降级走 `runRag()` |
| | | **新增** `private void runMultiAgentSafely(SseEmitter emitter, String sessionId, String userMessage)` — try `runMultiAgent()`，异常时降级到 `runRag()` |

**依赖**：`MultiAgentOrchestrator`（步骤 5）、`Intent` 枚举（步骤 6）

## 依赖关系总览

```
步骤 1 (线程池 + DTO)
  ├─→ 步骤 2 (LeaderAgent)
  ├─→ 步骤 3 (SubAgentExecutor)
  └─→ 步骤 4 (Aggregator)
        └─→ 步骤 5 (Orchestrator)
              └─→ 步骤 7 (ChatController)
                    └─→ 步骤 8 (前端)

步骤 6 (Intent 枚举 + 分类器)
  └─→ 步骤 7 (ChatController)

步骤 9 (测试) ← 全部完成后
```

- **可并行**：步骤 2、3、4 互不依赖，可同时开发；步骤 6 独立于 1-5
- **串行**：步骤 5 必须在 2/3/4 完成后；步骤 7 必须在 5 和 6 完成后

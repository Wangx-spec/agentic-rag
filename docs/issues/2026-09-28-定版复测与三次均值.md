# 定版复测与三次均值（2026-09-28）

## 背景：为什么要复测

r09（查询理解前置）单次成绩 corr 50.00% 刷新纪录，此前据此宣布「corr +6.25pp 领涨、固化默认开启」。但 r09 由人工运行、无 run 日志、且是单次采样。为消除「数字经不起追问」的口径疑虑，启动定版复测（P0 第 2 步）。

## 复测暴露的问题

第一次复测 r09final 的 correctness 只有 42.19%（r09 为 50.00%），差 7.81pp，远超预期的 ±3pp。逐题翻转：r09 → r09final 净 -5（9 对→错、4 错→对）。这触发了一个方法论反思——**correctness 单次采样方差远大于 ±3pp，之前的红线无法区分「真实回退」和「采样噪声」**。

## 三次运行数据（同配置：r07d 口径 + 查询理解开 + 文档工具关）

| 轮次 | Recall | Completeness | Correctness | Invalid Extra | 满分题数 |
|------|--------|-------------|-------------|---------------|---------|
| r09 | 70.92% | 54.40% | 50.00% | 3.12 | 32/64 |
| r09final | 68.35% | 55.10% | 42.19% | 3.22 | 27/64 |
| r09final2 | 74.79% | 60.02% | 46.88% | 3.17 | 30/64 |
| **均值（定版）** | **71.4%** | **56.5%** | **46.4%** | **3.2** | **30/64** |
| 三次极差 | 6.44 | 5.62 | 7.81 | 0.10 | 5 |

标准差（N=3）：recall ±3.2 / comp ±3.1 / corr ±3.9 / extra ±0.05。

## 关键结论

1. **四个指标都有显著采样方差，不只是 correctness**。加了第 3 轮后，recall 极差从 2.64 扩到 6.44、comp 从 1.81 扩到 5.62。64 题规模下单次运行的值不能当精确数字，只能用均值 + 区间表述。

2. **查询理解前置是正向趋势，但统计上不显著**。三次均值 vs r07d 基线：recall +3.07 / comp +3.22 / corr +2.61，全正向，但都落在方差内。结论：保留默认开启（正向趋势 + 零回退证据），撤销此前「corr +6.25 领涨」的过度乐观表述。

3. **Invalid Extra 是最稳的指标**（三次极差仅 0.10），可作为后续 rerank 阈值过滤的可靠衡量标尺。

## 定版数字（写入 README）

recall ≈ 71.4% · completeness ≈ 56.5% · correctness ≈ 46.4% · invalid extra ≈ 3.2 · 满分 ≈ 30/64（N=3 均值）。

## 过程记录（踩坑）

- **第 3 轮深夜卡死**：r09final2 首跑于 23:00 后，硅基流动 API 频繁 `request timed out`，主线程挂起 18 小时（HikariPool 反复报 Thread starvation / clock leap）。教训：评测应白天跑，深夜 API 不稳定。
- **answers 是 APPEND 模式**：EnterpriseRagRunner 用 `StandardOpenOption.APPEND` 写入 + 启动时 `readAnswerDocIds` 读已有答案（断点续跑）。重跑前必须删掉残缺 jsonl，否则新旧数据混写污染判分。
- **备份策略**：残缺产物先 `mv` 成 `.stuck` 后缀保留，再干净重跑。

## 定版配置口径（可复现）

```bash
EVAL_ERAG_CHAT_MODE=agent \
RAG_AGENT_DOCUMENT_TOOLS_ENABLED=false \
ROUNDS_DIR=eval-answers/rounds-era2 \
./scripts/run-erag-round.sh <round-id> hybrid 1 1 1
```

即：AGENT 模式 + 混合检索 + 查询改写开 + HyDE 开 + rerank 开 + citationTopN=5 + 查询理解开（默认）+ 文档工具关。

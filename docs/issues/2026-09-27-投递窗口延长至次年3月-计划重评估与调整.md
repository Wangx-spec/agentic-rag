# 投递窗口延长至次年 3 月——计划重评估与调整

> 日期：2026-09-27 · 触发：投递时间从「10 月中」延长至「次年 3 月」
> 用途：基于时间变量的重大变化，重新评估进度、重排阶段目标与时间分配，并给出风险与缓冲。
> 前置依据：《2026-09-24-项目进展与后续任务排期.md》《deepresearch-harness与agenticrag对照与改造可行性.md》

## 一、变化与影响本质

| 维度 | 原计划（9.3–10.15） | 新窗口（9.27–次年 3 月中） |
|------|------|------|
| 时长 | 约 6 周 | 约 24 周（5 个半月） |
| 模式 | 冲刺：保底、砍不确定项 | 深耕：可做深、可探索高价值增量 |
| 投递压力 | 每项都卡死线 | 有充分缓冲与机动 |

**性质变化：从「把最强叙事讲清楚」升级为「把项目做到完整形态再讲」。** 这一变化翻转了三类此前决策：

| 类别 | 此前决策（受 3 周窗口驱动） | 新判断 |
|------|------|------|
| 因时间砍掉的 | 不整体改 research agent（4–6 周做不完） | **可做**——窗口已满足，这是最大价值增量 |
| 因时间压缩的 | 评测 harness 只「demo 顺带落地」；MedAgents 只给 8 天 | **可展开**——分别给足 4 周 |
| 与时间无关的 | 跳过 M7/M8/M10（零准确率增益）；双简历策略；无框架纯自研差异化 | **维持不变** |

## 二、重新评估的核心结论

**头号判断：时间充裕后，最有价值的增量是把 agentic-rag 从「RAG 问答 Agent」升级为「research agent（deepresearch 式）」，并把评测从「外部重跑判分」升级为「轨迹落库 + 读轨迹评测」。**

此前 harness 对照分析得出「不建议现在改」的唯一硬理由是「只剩 3 周，4–6 周工作量做不完」，这个前提现已失效，结论随之翻转。

但必须守住一条底线：**是「叠加」不是「替代」。** agentic-rag 最强的资产仍是检索质量 + benchmark（recall 70.92 已超官方榜 OpenClaw 68.2 量级）。research agent 升级应在此之上叠加 Planner / Reflector / Reporter 三角色 + 证据结构化，形成「既能秒级快答、也能多轮深研、全程可观测可评测」的完整 Agent 平台叙事，而不是推倒重来。

三个关键子判断：

1. **评测 harness 是 research agent 的地基**：research agent 多轮多工具，更需要「读轨迹回溯」而非「重跑判分」。轨迹落库（run_trace 表）+ 指标纯函数化 + 效率指标，投入约 150–300 行，收益最高，应排在 research agent 之前独立成段。
2. **M9 记忆要升级为「长期记忆」**：原计划只做「会话级上下文延续」，research agent 需要跨会话的研究记忆（研究过程、已查证据、结论沉淀）。这是 research agent 的「记性」前提。
3. **准确率轨打磨（rerank 阈值过滤、v1 泛化）降级为穿插项**：时间充裕但收益确定性中等，作为各阶段的空档填充，不做独立里程碑。

## 五、优先级排序（重排后）

| 优先级 | 任务 | 依据 |
|------|------|------|
| **P0** | S0 定版封存 | 保底动作：先把最强 benchmark 叙事冻住，后续所有升级都建立在此之上，不可跳过 |
| **P1** | S3 research agent 升级 | 时间充裕后的最大价值增量；叙事从「高精度 RAG」升维到「可快答可深研的 Agent 平台」 |
| **P2** | S2 评测 harness | research agent 的地基 + 投入产出比最高（~300 行换「可观测性」叙事） |
| **P3** | S1 M9 记忆 | 既定里程碑 + research agent 的「长期记忆」前提 |
| **P4** | S5 MedAgents | 第二作品集，双简历策略既定；时间充裕后从「冲刺」转为「做深」 |
| **P5** | S4 demo | 投递前收口，依赖 S3 成果 |
| 穿插 | rerank 阈值过滤 / v1 泛化 | 收益确定性中等，作空档填充，不做独立里程碑 |

> 注：P1–P3 是 agentic-rag 主线，顺序按「保底 → 地基 → 主体」递进，均不可省略；P4 换技术栈（Python），故放主线之后串行，避免来回切换。

## 六、缓冲安排

1. **结构性缓冲 ~2 周**：不排进任何阶段的机动时间，专门吸收 S3（最大、最易超期）和 S5 的溢出。
2. **S6 内含 1 周投递缓冲**：简历与投递不卡死在某一天，避免最后关头赶工。
3. **硬节点保护**：S5 MedAgents 是「投递前必须完成」的硬节点，若 S3 超期超过 1 周，优先压缩 S4 demo（非核心），而非压缩 S5。
4. **每阶段留「验收 + 文档」日**：沿用 spec 四文档 + 复盘归档的纪律，不做「开发完直接切下一段」的裸奔。

## 七、风险点（时间充裕后，风险性质变了）

| # | 风险 | 说明 | 对策 |
|---|------|------|------|
| 1 | **范围蔓延** | 时间充裕后最易犯：什么都想做，结果每个都不深 | 守住「不碰清单」（状态机/预算/租约/检查点/Neo4j/框架依赖）；S3 严格四步走，每步独立评测，不做发散 |
| 2 | **升级拖垮 benchmark 叙事** | research agent 改造若回退检索质量，最强资产就丢了 | S0 先定版打 tag；S3 每步复测 r09 口径，退步即停 |
| 3 | **拖延/松懈** | 窗口拉长，容易失去节奏 | 保留每周里程碑 + 评审点；按 spec 流程的「确认点」制造节奏 |
| 4 | **上下文丢失** | 5 个月跨度，中间切 MedAgents 再切回，知识会断 | 依赖 issues 排期文档 + 工作区记忆体系承接；每阶段写「交接说明」 |
| 5 | **LLM 成本与算力** | research agent 多轮多工具 + 记忆 + 评测，调用量大幅上升，免费额度可能不够 | 评估硅基流动付费档；评测用预算上限（如单题 token 上限）控成本 |
| 6 | **叙事不同步** | 项目形态从「RAG 问答」变「research agent」，简历话术若停在旧故事会露怯 | S3 完成后同步更新简历 A/B 的 agentic-rag 部分；S4 把新叙事录进 demo |

## 八、需你拍板的关键决策

1. **是否采纳「research agent 升级」主线**（推荐）：接受则按 S0–S6 排期；不接受则回退保守路线（S0 定版 → M9 → demo → MedAgents，不做 S2/S3），省下约 11 周，但放弃最大的叙事增量。
2. **MedAgents 定位**：时间充裕后，它可继续做「从零自研医学问答」的完整形态；是否仍坚持「从零自研、不碰流传训练项目」的口径不变（默认维持）。
